## 2026-04-19

### ✅ Не обучаем свою модель
**Решение:** Используем Claude API для генерации HTML/CSS дизайна
**Альтернативы:** Обучить собственную модель (как Lovable/v0)
**Причина:** Обучение требует миллионы долларов и команду ML. Claude API даёт тот же результат за копейки. Под капотом Lovable и v0 используют те же LLM.

### ✅ Без базы данных на старте (Фаза 1-2)
**Решение:** Заявки сохраняются в JSON + email нотификация
**Альтернативы:** PostgreSQL (Supabase), MongoDB Atlas
**Причина:** YAGNI. На старте до 50 заявок/месяц JSON хватит. БД добавим когда появится реальная нагрузка.

### ✅ Без авторизации на старте
**Решение:** Нет личного кабинета, нет логина
**Альтернативы:** NextAuth с Google OAuth
**Причина:** Лишняя сложность для MVP. Цель — получить первые заявки, не строить SaaS.

### ✅ iframe для превью генератора
**Решение:** Рендер HTML от Claude в `<iframe srcDoc={...}>`
**Альтернативы:** Парсить HTML и рендерить через React, открывать в новой вкладке
**Причина:** Полная изоляция, безопасность (sandboxed iframe), не нужно парсить HTML. Открытие в новой вкладке — плохой UX.

### ✅ Vercel для деплоя
**Решение:** Vercel Hobby (бесплатно)
**Альтернативы:** Railway, Render, VPS
**Причина:** Zero-config для Next.js, автодеплой из GitHub, бесплатные serverless функции, встроенная аналитика.

### ✅ Resend для email
**Решение:** Resend.com API
**Альтернативы:** SendGrid, Nodemailer + SMTP, EmailJS
**Причина:** Современный, бесплатный tier (3000 писем/месяц), простой SDK для TypeScript.

## 2026-08-27 — Композиция страницы стала данными (DesignSpec)

**Проблема:** генератор выдавал визуально похожие результаты для разных ниш.
Корневая причина была не в промпте: модель не принимала ни одного визуального
решения. Вёрстку выбирал пользователь из четырёх радиокнопок, а все четыре
шаблона имели один и тот же скелет (hero → services → process → отзыв → FAQ →
контакты) с жёстко зашитыми 3 услугами, 3 преимуществами и 3 цифрами.
Фактически это был AI-копирайтер внутри четырёх макетов.

**Решение:** введён типизированный `DesignSpec` (`lib/design/spec.ts`).
Модель выбирает значения из перечислений: порядок секций, вариант hero,
палитру, типографику, плотность, скругления, тип карточек, обработку
изображений, фон, вариант CTA и вариант каждой секции. HTML собирается из
библиотеки вариантов (`lib/design/sections.ts`) в `compose.ts`.

**Почему именно перечисления, а не свободный HTML от модели:**
произвольная разметка означала бы неустранимый XSS и невозможность
автоматически проверять результат. Allow-list в `parseDesignSpec` делает
небезопасный вывод невозможным по построению.

**Побочная выгода:** правки стиля («премиальнее», «другой hero») меняют
спеку и пересобирают страницу за ~0.2 с через `POST /api/adjust`,
без обращения к модели и без записи в БД.

## 2026-08-27 — Модель не производит факты

**Проблема:** промпт прямо требовал «правдоподобные цифры для этой ниши»
и отзыв с подписью «Имя Фамилия, Должность, Компания». Фолбэк-контент
содержал «847 проектов», «4.9/5 на Google» и вымышленного клиента.

**Решение:** цифры, отзывы, гарантии, сертификаты, цены и сроки берутся
ТОЛЬКО из подтверждённых полей брифа (`VerifiedFacts`). Модель пишет о сути
и процессе услуги. Нет данных → честный placeholder, а блок отзывов
не рендерится. `lib/design/quality.ts` дополнительно ловит выдуманные
формулировки в сгенерированном тексте.

## 2026-08-27 — Генерация отделена от persistence

**Проблема:** `db.design.create()` стоял на пути к ответу, и любой сбой БД
превращал полностью готовое превью в HTTP 500 — в самый мотивированный
момент пользователя.

**Решение:** запись в БД — побочный эффект. Не удалась → превью всё равно
отдаётся, `designId` приходит `null`.

## 2026-08-31 — Редизайн v1 и коммерческая модель для Беларуси

**Решение:** первый вертикальный срез строится как «редакционная мастерская»:
светлая бумажная база, кобальт, сигнальный оранжевый, крупная типографика и
честное разделение между AI-концепцией и финальной ручной разработкой.

**Цены:** лендинг — от 1 200 BYN, бизнес-сайт — от 2 900 BYN,
индивидуальный проект — от 4 900 BYN. Базовое техническое SEO входит в
разработку; расширенная SEO-подготовка — от 600 BYN.

**Оплата:** 30/40/30 по понятным результатам этапов. Формулировка «оплата
после результата» больше не используется: для новой студии она переносит
весь риск на исполнителя и создаёт неверные ожидания.

**Портфолио:** пока нет достаточного числа коммерческих кейсов, показываем
«Лабораторию концептов» и прямо маркируем её как демонстрационные
AI-направления, а не работы клиентов. Выдуманные логотипы, отзывы и метрики
запрещены.

## 2026-08-31 — Редакционная система распространена на весь сайт

**Решение:** все публичные маршруты используют единый набор серверных
редакционных примитивов (`EditorialHero`, `EditorialSectionHeader`,
`EditorialMetrics`, `EditorialFaq`, `EditorialCta`). Городские и нишевые
страницы собираются из двух общих шаблонов вместо самостоятельной разметки
для каждого URL.

**Причина:** прежние страницы дублировали тысячи строк тёмных карточек и
быстро расходились по ценам, обещаниям и терминологии. Общие шаблоны сохраняют
самостоятельный SEO-контент, но делают визуальные и коммерческие изменения
системными.

**Контент:** неподтверждённые проценты роста, рыночные заявления, бесплатное
обслуживание и формулировки «готовый дизайн за 30 секунд» не показываются.
Генератор описывается как три первые визуальные гипотезы; реальные цифры,
отзывы и гарантии берутся только из заполненного владельцем брифа.

**Mobile:** удалено глобальное принудительное уменьшение всех `h1–h3`, которое
ломало масштаб новой типографики. Длинные слова не расширяют grid-контейнеры,
а плавающий Telegram скрыт на мобильном, чтобы не перекрывать CTA.

## 2026-08-31 — Атрибуция заявок и измерение прямой воронки

**Решение:** сохраняем в браузере только технические маркетинговые параметры
(`utm_*`, `gclid`, `yclid`, путь входа и host referrer) и передаём их в заявку.
Персональные данные в attribution не попадают. Прямые заявки и заявки из
генератора получают отдельные события старта, успеха и ошибки.

**Причина:** без источника и событий нельзя сравнивать не только количество,
но и качество заявок по каналам. Attribution не зависит от согласия на
аналитику, потому что не содержит персональных данных; события продолжают
подчиняться Consent Mode.

**Хранение:** для заказов из генератора attribution сохраняется в отдельном
JSON-поле `Order.attributionJson`, а для прямых заявок попадает в уведомления.

## 2026-08-31 — Две генерации в календарные сутки

Бесплатный генератор ограничен двумя успешными запросами на одну техническую
сессию в календарный день по времени Europe/Minsk. Счётчик хранится в
подписанной httpOnly cookie, а не как история генераций в базе: это сохраняет
контроль квоты без создания отдельной CRM-истории анонимного посетителя.

После достижения лимита пользователь видит понятное сообщение и ссылку на
обсуждение платной разработки. Короткий burst-rate-limit по IP остаётся
дополнительной защитой от частых параллельных запросов; строгая дневная блокировка
по IP не используется, чтобы не блокировать пользователей общей сети.
